# Deploy on Render with Supabase

The selected hosted setup uses a Render Free Docker web service and Supabase Free PostgreSQL. It keeps SQLite as the local default. The repository contains a Render Blueprint in `render.yaml`; it does not create a Supabase project, provision accounts, or migrate local data.

## Free-tier behavior

Render Free web services sleep after inactivity and use an ephemeral filesystem, so SQLite data in the service would not survive restarts or deploys. The app uses Supabase PostgreSQL instead. Supabase Free projects may pause after inactivity and have storage and compute limits; check both providers' current limits before relying on the service. This setup is for an MVP, not a production-availability guarantee.

## Create the database

1. Create a Supabase project and choose a strong database password.
2. In the Supabase dashboard, open **Connect** and copy the **Session pooler** connection string for external IPv4 connectivity.
3. Set `sslmode=require` in the connection URL if it is not already present. URL-encode special characters in the database password. Treat the complete URL as a secret.

The first application startup creates the database tables and seeds the MVP user, an empty board, and its fixed columns. Existing local SQLite data is not copied; no migration/export utility is included.

## Deploy the web service

1. In Render, create a Blueprint instance from this repository and select `render.yaml`.
2. Set the requested secret environment variables in the Render dashboard:
   - `DATABASE_URL`: the Supabase Session pooler URL.
   - `MVP_PASSWORD`: a unique password of at least 12 characters. The login username remains `user`.
   - `OPENROUTER_API_KEY`: optional; required for AI chat.
3. `SESSION_SECRET` is generated by the Blueprint. Keep the generated value private. `APP_ENV` is set to `production`; Render supplies `PORT`, and `/api/health` is configured as the health check.
4. Wait for the first deploy to become healthy, then visit the Render service URL and sign in.

Render terminates HTTPS. Do not add a Caddy service or publish the container port yourself. Keep database credentials, session secrets, passwords, and API keys in Render's secret environment settings, not in Git or build arguments.

## Before making it public

The MVP login has no failed-attempt throttling. This was identified in [the code review](code_review.md); address it before exposing the sign-in endpoint to arbitrary internet traffic. Use a unique production password regardless.
